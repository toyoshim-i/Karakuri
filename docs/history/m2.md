# M2 — Playable (Technical Implementation Record)

**Status:** Completed and closed.
**Goal:** Achieve a playable, stable live performance runtime executing a full set without failure.

---

## Technical Implementations Delivered

1. **4-Slot Deck Composition (`crates/karakuri-engine`)**:
   - Multi-slot deck architecture executing up to 4 concurrent Sets.
   - Per-slot gain, opacity, and blend modes (`Normal`, `Add`, `Multiply`, `Screen`).
   - Slot preview targets and isolated auditioning.
2. **Deterministic Hot-Swap & Budget Governor**:
   - Atomic hot-swapping at frame boundaries without render stalls ([ADR-0034](../adr/0034-the-frame-guard-owns-the-encoder.md)).
   - Budget governor evaluating CPU/GPU frame times and enforcing automatic fallback on over-budget candidates.
3. **Real-Time Signal Bus & Audio Analysis**:
   - Signal bus binding live audio input (FFT spectrum, onset, energy) to procedural shader parameters.
   - Beat-tracking oscillator generating synchronized `beats` and tempo grid.
4. **External Clock Sync & Ableton Link**:
   - Out-of-process tempo source architecture (`--tempo-source`).
   - Ableton Link integration sharing tempo and beat phase with external software and DJ equipment.
5. **Session Journaling & Headless Replay**:
   - Continuous ndjson session recording logging all operations and tick intervals.
   - Deterministic replay verifying performance reproducibility byte-for-byte.
6. **Model Context Protocol (MCP) Server**:
   - Loopback MCP service (`--mcp`) exposing tools to read procedures, write procedural code, and inspect swap outcomes.
