# M4 — Library at Scale (Technical Implementation Record)

**Status:** Completed and closed.
**Goal:** Build a robust, content-addressed storage and packaging architecture capable of managing, indexing, and sharing large libraries of procedural sets and artifacts.

---

## Technical Implementations Delivered

1. **Content-Addressed Storage (`crates/karakuri-store`)**:
   - SHA-256 content-addressed artifact repository for procedural source files (`.kir`).
   - Append-only event journaling (`.ndjson`) for performance session capture and replay.
2. **Packaged Set Bundles (`.kbset`) & Setfiles**:
   - Dual-format set architecture:
     - `.kset`: Human-authored setfile referencing local parts by relative path.
     - `.kbset`: Fully resolved, self-contained binary/text bundle inlining all artifact sources by content hash ([ADR-0231](../adr/0231-a-sets-two-forms-take-two-extensions-and-the-store-holds-only-the-resolved-one.md)).
   - Inlining and extraction engine (`karakuri_environment::setfile::bundle`) guaranteeing byte-for-byte reproducibility on any machine.
3. **Artifact Metadata Indexing (`cards/`)**:
   - Extraction and caching of static procedure metadata cards (`.card.json`) recording declared parameter ranges, sensor inputs, element capacities, and GPU cost estimates without requiring shader recompilation.
4. **Library Browser API**:
   - High-performance listing and query filtering over Sets, Presets, and version history.
   - Live Set snapshotting from active running performance sessions.
