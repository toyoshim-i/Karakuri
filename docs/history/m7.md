## 1. Milestone Overview

M7 transformed the Model Context Protocol (MCP) server from an uncontrolled mutation endpoint into
a live co-performance environment. Rather than implementing an over-engineered node-level
authority state machine or speculative generation queue, M7 aligned control directly with the
realities of live VJ performance:

- **Slot-level access policy**: Three-state protection (`Auto`, `On`, `Off`) in the Inspector header.
- **Mixer live-contribution tracking**: Under `Auto`, slots actively in the mix (`tally == Live && opacity > 0.0`)
  are automatically write-protected; lowering the fader or muting the channel immediately enables off-air MCP iteration.
- **Dedicated co-performance workflow tools**: `get_permissions`, `read_slot`, and `copy_slot`.
- **Atomic file staging**: Staging all procedure writes and slot duplication through `.tmp` files and atomic
  filesystem renames, preventing file watchers from observing partial writes or multi-file AST mismatches.
- **Session policy persistence**: Slot policies persist across application restarts in `<store>/policies.json`
  and are recorded into session journal heads as `Record::Policy`.
- **Machine-readable refusal codes**: Refusals return structured JSON envelopes carrying `RefusalCode`
  (`SLOT_IN_MIX`, `SLOT_POLICY_OFF`, `SLOT_UNALLOCATED`, `BAY_CLOSED`) for programmatic agent error recovery.
- **Master chain build indicator**: Real-time feedback in the Master bay (`building` badge) when background
  worker compiles are in progress.
- **Tooltip HUD visual overhaul**: Concise, structured HUD cards across all 39 interactive controls, replacing
  unwieldy stream-of-consciousness strings with clear operational telemetry.

## 2. Built & Landed

### Slot-Level MCP Access Policy (`karakuri-operation`, `karakuri-console`, `karakuri-environment`)
- `SlotPolicy` (`Auto`, `On`, `Off`), `RefusalCode`, `RefusalDetail`, and `SlotAccess` defined in pure leaf crate `karakuri-operation`.
- `SlotPolicies` thread-safe handle (`Arc<RwLock<[SlotAccess; 4]>>`) shared across the application event loop and MCP server.
- `SlotMcpPill` in `karakuri-console` positioned `PILL_GAP` left of the `keep` pill in the Inspector header.
- Probe `on_slot_mcp` registered in control registry (`ControlId::InspectorSlotMcp`, 39 probes) and hover tips.
- Clicking cycles `Auto` -> `On` -> `Off` -> `Auto`, immediately updating view, dispatching shared state, and persisting to store ([ADR-0362](../adr/0362-a-slots-mcp-policy-is-auto-on-or-off-and-the-mixers-live-contribution-decides-auto.md)).

### Live Mixer Contribution Tracking (`karakuri::app`)
- On startup and every frame, `strip.tally == Tally::Live && strip.opacity > 0.0` calculates live contribution.
- When an operator pulls a fader to 0.0 or mutes the strip, the slot leaves the mix, permitting background agent editing without manual unlocking.
- Clean startup initialization (`Engine::startup`) prepares cold slot measurements and estimates without forcing deck B to prime, leaving slots cleanly at `Residency::Allocated`.

### Agent Workflow Tools & Standardized Protocol (`karakuri-mcp`)
- `get_permissions`: Queries bay openings, per-slot policies, `in_mix` status, and current write permissions.
- `read_slot`: Reads all active layer procedures (`L1`..`L5`) in a slot in a single tool call.
- `copy_slot`: Copies all active procedures from source to destination slot with optional layer filtering, guarded by destination access policy.
- Guarded `write_procedure` and `operate` against slot policy; write refusals return standard `Ok(Called::Answered(Err(reason)))` with `isError: true` ([ADR-0363](../adr/0363-agent-workflow-operations-are-read-slot-copy-slot-and-get-permissions-staged-through-atomic-rename.md)).

### Atomic Move Protection (`karakuri-environment::scratch`)
- `scratch::write_atomic` stages writes to `.tmp` files before renaming to target `.kir` paths.
- `copy_slot` stages all destination procedures to `.tmp` before renaming, ensuring compiler workers and filesystem watchers never observe partial or mismatched layer files.

### Session Policy Persistence & Session Head (`karakuri-store`, `karakuri-environment`, `karakuri`)
- Added `Store::policies()` and `Store::write_policies()` for persisting slot policies in `<store>/policies.json`.
- Added `Record::Policy { slot: DeckSlot, policy: String }` to the session record vocabulary.
- `session::head` emits `Record::Policy` for all active slots upon session recording start.
- `App::new` restores slot policies from the store on boot, synchronizing `readout.slot_policies` and `readout.view.slot_policies`.

### Machine-Readable Refusal Codes & Error Envelopes (`karakuri-operation`, `karakuri-mcp`)
- Defined `RefusalCode` (`SlotInMix`, `SlotPolicyOff`, `SlotUnallocated`, `BayClosed`) with standardized uppercase identifiers (`SLOT_IN_MIX`, `SLOT_POLICY_OFF`, `SLOT_UNALLOCATED`, `BAY_CLOSED`).
- Defined `RefusalDetail` carrying error code, formatted message, slot number, policy, and in-mix status.
- `tool_result` wraps refusals into structured JSON objects while maintaining full backwards compatibility on `content[0].text`.
- Programmatic clients inspect `reply["result"]["refusal"]["code"]` to autonomously adapt workflow strategies (e.g. switching to off-air slots or requesting bay openings).

### Master Chain In-Flight Build Badge (`karakuri-console`, `karakuri`)
- Added `View::master_chain_building: bool` wired directly to `gfx.engine.chain_swap.building().is_some()`.
- Added `Head::building` and `with_building(bool)` to console head widgets.
- Master bay head renders an in-flight `"building"` badge in `pal.sun` whenever the background worker thread is compiling pipeline stages.

### Tooltip HUD Visual Overhaul & Literature Copy Streamlining (`karakuri-console`)
- Replaced verbose stream-of-consciousness tooltips across all 39 interactive probes with structured HUD cards (`eyebrow`, `title`, `state`, `summary`, `body`, `midi`, `mcp`).
- Added Dark mode and Fancy/Day mode palette preview and runtime toggle support.

### Console Visual Parity & Active Focus Redesign (`karakuri-console`)
- Replaced `.wfocus` dashed amber outline with hairline lavender (`pal.lav`) boundary accent for headless rows and inset card border for bays.
- Restored vertical divider grip decoration (`⋮` on `.divider-v`).

### Dedicated Documentation & MCP Manual
- Published complete MCP client documentation in `docs/manual/mcp.html` detailing connection setup, safety policies, slot workflows, and tool schema.
- Updated `karakuri-mcp/README.md` and cross-documentation navigation links.

### Unified Console-Bay Gating & Schema Hardening (2026-09-22)
- Unified the conceptual gate architecture: Console Bays map 1:1 to gate controls. The Inspector bay's gate is the per-slot policy (`Auto`/`On`/`Off`), while Mixer (`MixFaders`), Master (`MasterEffects`), Outputs (`InputsAndOutputs`), and Program (`LiveDeck`) are bay-level capsules.
- Formally published the complete 14-tool permission matrix and machine-readable refusal recovery flows in `docs/manual/mcp.html`.
- Enforced slot policy write checks across all deck-mutating operations (`LoadSet`, `SetCompositing`, `AttachSignal`, `SetProperty`, `Publish`) in `operate.rs`.
- Published all 5 agent workflow and validation tools (`get_permissions`, `read_slot`, `copy_slot`, `check_procedure`, `check_set`) in `tools/schema.rs` (`tools/list` schema) with parameter definitions.
- Standardized missing argument error handling to conform to MCP tool result semantics (`isError: true`).
