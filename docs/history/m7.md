## 1. Milestone Overview

M7 transformed the Model Context Protocol (MCP) server from an uncontrolled mutation endpoint into
a live co-performance environment. Rather than implementing an over-engineered node-level
authority state machine or speculative generation queue, M7 aligned control directly with the
realities of live VJ performance:

- **Slot-level access policy**: Three-state protection (`Auto`, `On`, `Off`) in the Inspector header.
- **Mixer live-contribution tracking**: Under `Auto`, slots actively in the mix (`tally == Live && opacity > 0.0`)
  are automatically write-protected; lowering the fader or muting the channel immediately enables off-air MCP iteration.
- **Dedicated co-performance workflow tools**: `get_permissions`, `read_slot`, and `copy_slot`.
- **Atomic file staging**: Staging all procedure writes and slot duplication through `.tmp` files and atomic
  filesystem renames, preventing file watchers from observing partial writes or multi-file AST mismatches.

## 2. Built & Landed

### Slot-Level MCP Access Policy (`karakuri-operation`, `karakuri-console`, `karakuri-environment`)
- `SlotPolicy` (`Auto`, `On`, `Off`) and `SlotAccess` (`is_writable`, `refusal_reason`) defined in `karakuri-operation`.
- `SlotPolicies` thread-safe handle (`Arc<RwLock<[SlotAccess; 4]>>`) shared across the application event loop and MCP server.
- `SlotMcpPill` in `karakuri-console` positioned `PILL_GAP` left of the `keep` pill in the Inspector header.
- Probe `on_slot_mcp` registered in control registry (`ControlId::InspectorSlotMcp`, 39 probes) and hover tips.
- Clicking cycles `Auto` -> `On` -> `Off` -> `Auto`, immediately updating view and dispatching shared state ([ADR-0362](../adr/0362-a-slots-mcp-policy-is-auto-on-or-off-and-the-mixers-live-contribution-decides-auto.md)).

### Live Mixer Contribution Tracking (`karakuri::app`)
- On startup and every frame, `strip.tally == Tally::Live && strip.opacity > 0.0` calculates live contribution.
- When an operator pulls a fader to 0.0, the slot leaves the mix, permitting background agent editing without manual unlocking.
- Clean startup initialization (`Engine::startup`) prepares cold slot measurements and estimates without forcing deck B to prime, leaving slots cleanly at `Residency::Allocated`.

### Agent Workflow Tools & Standardized Protocol (`karakuri-mcp`)
- `get_permissions`: Queries bay openings, per-slot policies, `in_mix` status, and current write permissions.
- `read_slot`: Reads all active layer procedures (`L1`..`L5`) in a slot in a single tool call.
- `copy_slot`: Copies all active procedures from source to destination slot with optional layer filtering, guarded by destination access policy.
- Guarded `write_procedure` and `operate` against slot policy; write refusals return standard `Ok(Called::Answered(Err(reason)))` with `isError: true` ([ADR-0363](../adr/0363-agent-workflow-operations-are-read-slot-copy-slot-and-get-permissions-staged-through-atomic-rename.md)).

### Atomic Move Protection (`karakuri-environment::scratch`)
- `scratch::write_atomic` stages writes to `.tmp` files before renaming to target `.kir` paths.
- `copy_slot` stages all destination procedures to `.tmp` before renaming, ensuring compiler workers and filesystem watchers never observe partial or mismatched layer files.
