# Publishing is a choice of attention, not of authority

A Set's published interface decides **what is shown**, never **what can be reached**. `param` records
keep arriving at controls nobody published — which is how a Set file records an author's frozen
values, how `--param` works, and how MCP adjusts something that is not on the console.

**What it rules out.** Treating a surface as access control. If publishing gated reach, **a Set's
author could lock the operator out of their own machine** — the exact inverse of this project's
position everywhere else: show every measurement and act on none, hide nothing, needing a hand is
craft rather than defect.

**A published range narrows; it never redefines.** Outside the `.kir`'s declared range is refused
rather than clamped, because that range is the procedure's own claim about where it still looks like
itself. An empty interface publishes everything, so the feature is purely additive.

**And it makes a check disappear rather than be fixed.** Two renderers over one geometry almost
always both declare `exposure`; with two namespaces — internal node-plus-name, external Set-given
name — that is two published controls or one driving both, which is the author's judgement and not an
error.
