# Doubt a conclusion that contradicts a position already taken

When a judgement about this design collides with a stance the project has taken repeatedly, **the
thing to re-examine is the judgement.**

Ableton Link was called unusable because it does not follow the music unattended. But *show the
measurement, a human moves it* is the answer this project had already reached four separate times —
semi-automatic gain, the tempo octave, the NaN count, the panic key. **Requiring a hand is what this
project chooses**, and calling it a failure in the one feature that arrived from outside was
incoherent. Nothing inside the reasoning flagged it.

**What it rules out.** Applying an imported criterion — *does it work unattended* — without noticing
it is imported. It also rules out letting a negative frame stand unexamined: it had hidden the value
that was actually there, since a tap on the Link subscreen reaches every peer in the session while the
local tap reaches one machine.

**A related failure, same shape.** Compaction keeps decisions and drops reasons, **and the loss is
invisible**, because the decision still sounds plausible. A whole recommendation was built on a
weakened premise with no warning from inside. When a summary says a thing was decided, ask what it
rests on before arguing from it — and if the reason did not survive, say so rather than reconstructing
a plausible one.
