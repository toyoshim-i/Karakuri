Karakuri · the manual

Every operation, and every way in

The first rule says every operation is reachable from the panel, from the keyboard alone, from a mapped MIDI control, and from a model over MCP. This page is that rule written out one operation at a time — which makes it two things at once: what the instrument can do, and where it does not yet hold.

How to read a row

built — this surface reaches it today designed — this surface is meant to reach it, and no program a player runs does yet nothing — this surface cannot reach it at all

50 operations, and 51 of the 216 ways in exist. Six of them arrived with the console's own shape — moving a boundary, folding a bay or a pane, bringing one back, solo, and resetting the arrangement — and every one of their twenty-four routes is empty except the pointer, which four of the six have. Two have no route at all: a folded region has no rectangle for a pointer to find, and resetting is the default case of a family — keeping an arrangement and putting one back — that has nowhere on the console to live until the rest of it exists. No panel route is marked built, and the reason is not that the panel is unbuilt: it draws part of itself, and some of its controls already emit these operations. What no program does is put it in front of a player. Where a badge names a region, that is where the control lives in the console; three name none yet, and naming one is a change to this specification rather than a note on it. The counts here are read off the code rather than estimated, and they are what the Interface milestone is for.

A launch badge means the only way in is a flag, before the run, and nothing can change it afterwards. On the grid means the change is scheduled and lands on a musical instant rather than when you asked for it.

Decks

What is resident, what is on air, and what material is in each.

Select a deck

immediate

Which deck the keys are addressed to. A console pointer — it writes no record, and it is not the same as keyboard focus.

panel click a strip key 0–3 MIDI — MCP —

Put a deck on air, prime it, or take it off

immediate; priming is a request

Three states, not two switches: live is stepped and composited, priming is stepped out of sight and adds nothing to the mix, allocated is held — compiled, buffers kept, its t where it stopped, so a deck taken off and brought back resumes rather than restarts. Live is honoured: nothing demotes a deck that is on air. Priming is a request the governor reconsiders every pass, and a deck asked to prime with no room is parked — the request stands and takes effect when there is room, so what the console shows is the residency the deck reports, not the one it was asked for. MIDI names the deck and the state, so it needs no selection and no notion of which way to flip — a pad per state, and a key acts on the selected deck.

panel tally chip key space, w MIDI note → residency N live|priming|allocated MCP —

Set a deck's mask shape

immediate

What shape of the frame a deck's layer reaches — none, a straight front at an angle, or an iris — and it leaves the front where it is. Not the row z presses: that one chooses what the next wipe will be, where this one changes the mask a deck has now. A pad would name a shape the way it names a blend mode; the angle it could not name at all, because a map line has no way to write a bare number. The badge is empty on purpose rather than pending. Teaching the map a bare number would be teaching it the one kind of value it can check against nothing, and taking the angle off this row would hand it to a default. So this waits for a control that shows an angle, which is what would say what a map ought to write — and until then the front is the half of the mask a knob reaches.

panel strip mask mini key — MIDI — MCP —

Set a deck's mask position

immediate

How far the front has travelled: 0 reveals nothing, 1 reveals everything. The number a wipe's scheduled move is writing, so a hand here stops the move — which is the whole reason the mask is two rows and not one, since a control change carries a position and can only set. Both ends of the fader are exact, because a wipe that has to finish depends on the top of the travel and a layer that has to disappear depends on the bottom.

panel — key — MIDI cc → mask-position N MCP —

immediate

The level going into that transfer. A key steps it in stops and returns it to 1.0; a MIDI control sets it outright. Element capacity, seeds, the camera

launch

Set a node's authority

immediate

Manual, suggesting or automatic, on one node of one deck's Set. It is a permission granted forward — what an agent may move from here on — and never a record of who moved something last, which is the source a driven parameter already shows beside its take back. Per node, never a global mode, because the useful arrangement is almost always partial. Every node a Set can address takes one, a kind Field node included: it draws nothing and its parameters are still an operator's to ride. The merge that folds a deck's renderers is the one node with no address, so it takes none. Nothing writes one yet: the stream can say it and a deck rebuilds without it, so a node's authority would not survive the next swap.

Procedures

Reading, writing and swapping the material itself.

Read one node's source

immediate

Addressed by deck, layer and index. Read before writing: the edit is usually small, and what is there is the best guide to the language.

panel inspector key — MIDI — MCP read_procedure

on a worker

Checked as you write it; built on a worker and swapped at a frame boundary. If it does not compile, what comes back is the checker's diagnostics against the source.

on a worker

The same swap, reached from any editor. Polled, debounced, and compared by content rather than by timestamp.

Landed, rolled back for costing too much, or failed to build. A write returning cleanly means it compiled, not that it is on screen.

Arranging the console

The panel's own shape, which is the operator's and not the layout's.

Move a boundary

immediate

Every divider drags, and stops where the regions either side say they will go no further. A window dragged too small to hold everything gives everything less and forgets nothing: widen it again and the arrangement comes back exactly.

panel drag key — MIDI — MCP —

Fold a bay away

immediate

A folded bay takes no space at all and no divider is drawn beside it; what it had goes to the bay that takes height back in that pane. Its size is remembered, so bringing it back puts it where it was.

panel bay head key — MIDI — MCP —

Fold a pane away

immediate

The whole left or right pane, with everything in it, and the centre takes the width. The centre is not a third pane and does not fold — what you want there is solo.

panel pane edge key — MIDI — MCP —

Bring back what is folded

immediate

A folded region has no rectangle, so a pointer cannot reach it. That makes this the one operation here that a mouse cannot be the only way into — folding is one-way for a pointer, and something else has to undo it.

panel — key — MIDI — MCP —

Solo a region

immediate

Everything that is not this region, on the way to it, or inside it folds away, and it holds the window. On the program that is the panel folding away and only the picture left, which is also how you capture this window. Undoing it restores what was folded before, including whatever was already folded.

panel solo key — MIDI — MCP —

Reset the arrangement

immediate

The default arrangement back, in the window you already have. It is the one operation here that forgets, and what it forgets is what the rest of this section promises to keep: every fold, every boundary you have dragged, the solo, and the remembered sizes a folded bay and a window dragged too small are both holding for you. This is the special case of putting a saved arrangement back — and it is the only member of that family that exists, because naming an arrangement, keeping one and restoring one are not built, so there is nothing to reset to but the default and nothing to return to afterwards. A pad could name it: it addresses nothing, where every other row here needs a region a map line has no way to spell. None does yet.

panel — key — MIDI — MCP —

What the gaps say

MIDI is the narrowest by a wide margin. It reaches eight of these fifty operations, and it cannot express a node address, a parameter name or an id — nor a bare number, which is why it reaches one half of the mask and not the other. A map line carries a slot number, a word out of a value list, or a range, and an angle is none of the three; a pad naming a shape alone would have to invent the angle beside it, and the map reads nothing back to invent it from. So the front has a fader and Set a deck's mask shape stays empty here rather than being given a route that guesses. That is settled and not outstanding: the two ways to fill the badge in are a number the format cannot check and an angle somebody defaults, and the thing that would decide between them is a control that shows an angle, which does not exist yet. It no longer has a vocabulary of its own, though: a map line names one of the operations on this page, and it names it outright — which state, which mode — rather than saying step it. It also has no idea of a selected deck — it names the deck in the message — where the keys have nothing but the selected deck. The same operation is addressed two different ways on two surfaces.

A model can rewrite a whole procedure and cannot turn one knob. MCP edits material, reports swaps and reads the library, and touches nothing in the mix, the clock or what is on air. It can make a deck unrecognisable and cannot put it on air.

Authority is named here and reachable from nothing, and it is short of something none of the other empty rows are. It is not waiting on a decision: rule 06 settled the address, and it is per node. It is not waiting on a control either — the node head it belongs on is specified on the console page, like every other panel route on this page. What it waits on is the deck. A node's authority has to survive every rebuild, the way that node's parameters and bindings already do, and a rebuild that let it be worked out afresh would hand a node back to an agent an operator had taken it from, saying nothing. Until a deck carries it, the row is a word the instrument can say and cannot keep.

Arranging the console is reachable from a pointer and nothing else, which is the first rule broken by the surface the first rule is about. A divider that can only be dragged is a control the keyboard cannot touch, and folding is worse than that: a folded region has no rectangle, so a pointer cannot even reach it to undo itself. How a pane is sized and unfolded without a mouse is not decided, and it is decided by naming these operations rather than by drawing anything. Reset the arrangement is the exception that says what the rest of the section is short of rather than what a surface is: it names no region, so a pad could reach it the way a pad reaches tap, and what it is waiting for is the family it is the default case of.

The command line is the only way into most of what a Set is — parameters, bindings, edges, the published interface, capacity — and it is only open before the run starts. Reachable from nothing at all while running: parameter writes, binding changes, edge rewiring, the camera, seeds, capacity, canvas size, un-compositing a deck, folding every renderer back in, a gain fade, and starting or stopping a recording.

Counted from the source, not from this manual. Where a row here and the program disagree, the program is right and this page is a bug — the seven rules are what both are meant to obey.
