Karakuri · the manual

Every operation, and every way in

The first rule says every operation that changes something is reachable from the panel, from the keyboard alone, from a mapped MIDI control, and from a model over MCP — and leaves an operation that only asks to each way in's own design. Every operation is a row, every surface is a column, and the badge says whether that surface reaches it. Hover or focus an operation's name for what it does.

How to read a row

built — this surface reaches it today designed — this surface is meant to reach it and does not yet nothing — this surface cannot reach it at all
immediate it lands when you ask for it grid it is scheduled and lands on a musical instant launch the only way in is a flag, before the run on a worker it is built off the render thread and lands when it is ready
read it only asks, so a column left empty here is that way in's own design and not something owed

A key badge names a press, and where a press is addressed it names the bay too — space · in the Mixer. A key press goes to the bay that has focus, so space, enter, a digit and the arrows reach a different row in every bay and a key named on its own would not say what it lands on. A bare letter is a key that is addressed to nothing: it means the same thing wherever the keys are pointed, which is what makes it global. No operation is given a letter for its initial: the alphabet runs out and a grammar does not.

Built and designed are the meter and not the spelling. A built badge is a press an operator makes today; a designed one is a press that is decided and does not work yet. The grammar is built in two bays — the mixer and the library — so their rows carry it in the built column, and the seven bays whose rows read designed are waiting on the same six keys arriving there. Until they do, f, g, s and u still take the region under the pointer rather than the one focus is on.

A letter stays bare only where the operation it names has no operand for focus to supply, or where its only operand is the choice the key itself spells — b, , ., r and z. k keeps one for a narrower reason: the act is decided and the library bay draws no keep control for it to be addressed to, so there is nothing yet for the grammar to land on. Two keys are the grammar's and name no row at all: tab moves focus to the next bay and shift-tab to the one before, and esc goes up one level of the focused bay's address. Neither is an operation, so neither has a row here — and esc is the one letter the design took back, from Quit, on 2026‑09‑09. An empty key column is a row no grammar reaches, and the reason is never a letter that ran out: an effect whose parameters have no spelling, an operand that is a name or a path no key press can type, or a way in that is a flag before the run or a model's.

The MIDI column is the instrument's map, on the key column's terms one column along: it measures the map cargo run -p karakuri loads, and the grammar is one file — karakuri-midi's — that karakuri-cli reads too, so the two programs cannot disagree about what a line means. That question was left open when the key column was settled, because the instrument had no MIDI at all; it opens the first input there is at start‑up now and loads a map from <store>/maps/, or from the surface.map that ships. A badge names the line to write, so cc → gain N is a line rather than a description of one. An empty MIDI column is a row a line cannot say: a map line names a slot number, a range, a word from a closed list, or a position in a deck's published interface, and a Set id, a path, a name somebody typed and an angle are none of those.
