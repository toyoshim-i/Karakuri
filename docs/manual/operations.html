Karakuri · the manual

Every operation, and every way in

The first rule says every operation is reachable from the panel, from the keyboard alone, from a mapped MIDI control, and from a model over MCP. This page is that rule written out one operation at a time — which makes it two things at once: what the instrument can do, and where it does not yet hold.

How to read a row

built — this surface reaches it today designed — this surface is meant to reach it and does not yet nothing — this surface cannot reach it at all

The key column is the instrument's keyboard — the keys cargo run -p karakuri binds, and no other program's. Two programs in this repository have a keyboard and they are not the same keyboard: the instrument binds nine keys, karakuri-cli binds thirty-nine, and eight letters mean one thing at the panel and something else at the command line. Only esc agrees. So a built key badge names a key an operator at the panel can press today, for the same reason a built panel badge names a control they can reach: both columns are about the one program a player launches, and a badge that mixed the two would tell a reader to press a letter that does something else in front of them. A designed key badge names the key this page has specified — the console defers to it, because which keys exist is this page's to say — and the instrument does not bind it yet. The command line's own keyboard is printed by cargo run -p karakuri-cli -- --help, which is derived from its key handler and checked against it; it is not this column, and a second copy of it here would be a list that goes stale.

55 operations, and 50 of the 236 ways in exist. Eight of them are the console's own shape — moving a boundary, folding a bay or a pane, bringing one back, solo, and the three that reset, keep and put back an arrangement — and nine of their thirty-two routes exist: the drag, a key on each of five, and the transport row's arrangement pill on three. Every row of that section has a route now, and the two that carry a name were the last: a key press cannot type one, so keeping an arrangement and putting one back waited on a control that could, and the pill is it. Resetting is the default case of those two and is reached from both — r, and start a new one on the same pill. Twenty key badges are designed rather than built, and every one of them is a key the command line binds today. The column is the instrument's keyboard and the instrument binds nine keys, so the twenty are what the command line reaches and the panel does not; the letters stay because this page is where a key is specified, and seven of them are already spoken for at the panel — f and g fold, z brings back what is folded, u unsolos, r resets, p asks the panel to report itself and n changes its colours. Whether the instrument takes those letters or the command line gives them up is a decision nobody has made, and it is a change to this specification rather than a note on it. Fourteen panel routes are marked built, and they are the whole of that column: the Mixer bay's five — the strip trim, the strip fader, the strip button, the tally chip and the strip mask mini — every divider on the panel, which drags; the transport row's tone map capsule, its exposure track and the arrangement pill's three rows; the deck head's sync chip and its scrub; and the Master bay's out. The Mixer's five already emitted these operations while the console was an example; what changed is that cargo run -p karakuri puts them in front of a player, which is what a panel badge claims and what no program did until it existed. The one that is not a control is the console's own shape: a press on a gap takes the boundary in hand, and the moves and the release after it are the panel's rather than the interface's over it. The Outputs dot is drawn and pressable and its badge stays designed, which is a distinction this page owes rather than an oversight: the dot folds the program view away and brings it back, and this row names choosing where the frame goes across a switchable list of sinks. One entry of that list is not the list, so the control performs part of what the row names and the badge would be an over-claim. Thirty-eight more are designed and out of reach, most of them in bays nothing draws yet, and three the panel cannot reach at all. Where a badge names a region, that is where the control lives in the console; three name none yet, and naming one is a change to this specification rather than a note on it. Three of them are named here for the first time: the arrangement family — reset it, save it, put one back — lives in the transport row, beside the pill that names the MIDI map in use. That pill is already the shape this family needs and the reason the row is the right one: a named file, with save, load and start a new one under a single control, and a new one is exactly what the reset is. All three are built now, and the order they were built in is the order this repository works in: these badges specified a control that did not exist, the page that owns the console's words drew it next, and the panel was built to that. Nothing was designed at the keyboard. The Master bay's out is the fourteenth and it arrived by the same order read from the other end: the console page has drawn that fader since before anything could move it, the engine gained the level and the one multiply next (the console's Master, and the two levels that are not one level), and this row is the last of the three rather than the first. Its other three columns are empty and that is the state rather than an omission — no key is bound to it, no map target names it and no tool publishes it. The counts here are read off the code rather than estimated, and they are what the Interface milestone is for.

A launch badge means the only way in is a flag, before the run, and nothing can change it afterwards. On the grid means the change is scheduled and lands on a musical instant rather than when you asked for it.

Set a deck's sync mode

immediate

Free, tempo-synced, or beat-synced — and a mode a deck's material cannot honour is skipped with a reason. Decks

What is resident, what is on air, and what material is in each.

Select a deck

immediate

Which deck the keys are addressed to. A console pointer — it writes no record, and it is not the same as keyboard focus.

panel click a strip key 0–3 MIDI — MCP —

Put a deck on air, prime it, or take it off

immediate; priming is a request

Three states, not two switches: live is stepped and composited, priming is stepped out of sight and adds nothing to the mix, allocated is held — compiled, buffers kept, its t where it stopped, so a deck taken off and brought back resumes rather than restarts. Live is honoured: nothing demotes a deck that is on air. Priming is a request the governor reconsiders every pass, and a deck asked to prime with no room is parked — the request stands and takes effect when there is room, so what the console shows is the residency the deck reports, not the one it was asked for. MIDI names the deck and the state, so it needs no selection and no notion of which way to flip — a pad per state, and a key acts on the selected deck.

panel tally chip key space, w MIDI note → residency N live|priming|allocated MCP —

Load material into a deck

launch

The single largest gap in this table. Nothing loads a Set into a running deck — the library can be read and not played from. The panel badge says where the control goes and not that drawing one would be enough, which is worth saying because a reader working the board will pick this row up as drawing work: Deck::install is the one function that puts a Set in a slot and is documented as deliberately unreachable from a key or a surface, --set and --load-set are launch flags, and the operation writes no record — so whichever surface names it has to perform it, and there is nothing to perform. The cursor and the deck selection are owed on top of that, and the key letter is owed by this page.

on the grid

Set a deck's mask shape

immediate

What shape of the frame a deck's layer reaches — none, a straight front at an angle, or an iris — and it leaves the front where it is. Not the row z presses: that one chooses what the next wipe will be, where this one changes the mask a deck has now. A pad would name a shape the way it names a blend mode; the angle it could not name at all, because a map line has no way to write a bare number. The badge is empty on purpose rather than pending. Teaching the map a bare number would be teaching it the one kind of value it can check against nothing, and taking the angle off this row would hand it to a default. So this waits for a control that shows an angle, which is what would say what a map ought to write — and until then the front is the half of the mask a knob reaches.

panel strip mask mini key — MIDI — MCP —

Set a deck's mask position

immediate

How far the front has travelled: 0 reveals nothing, 1 reveals everything. The number a wipe's scheduled move is writing, so a hand here stops the move — which is the whole reason the mask is two rows and not one, since a control change carries a position and can only set. Both ends of the fader are exact, because a wipe that has to finish depends on the top of the travel and a layer that has to disappear depends on the bottom.

panel — key — MIDI cc → mask-position N MCP —

Master out

immediate

One level on the composited frame, at the entry to the master chain — the whole fold rather than one deck of it, which is why this is the row in the group that names no deck. It is not the exposure below it. That is a second level at the far end of the same chain, and what makes them two is where each multiplies: this one is applied where the mix writes the frame, the exposure where the present pass reads it, and feedback, bloom and rgb shift go between them. A frame effect reads what it is handed, so which side of it a level sits on is the picture — a feedback trail fed at half the level decays from half. With the chain empty they are indistinguishable in every frame this program can draw, and that cost was taken deliberately rather than met later: the console page's Master, and the two levels that are not one level is the argument. Unbounded above 1.0 and floored at zero, on the trim's terms — the pipeline is linear HDR and nothing has tone mapped it yet. Nothing can schedule a move on it: a transition is per deck and this is the deck's own output, so there is no fade for a hand on it to cancel.

panel master out key — MIDI — MCP —

Tone map

immediate

The transfer from unbounded linear HDR to something displayable — clamp, Reinhard, ACES or AgX. The key cycles the four; a map or a model would name the one it wants.

panel transport key t MIDI — MCP — CLI --tonemap

Exposure

immediate

The level going into that transfer. A key steps it in stops and returns it to 1.0; a MIDI control sets it outright. The record it lands in names the operator beside it, and whoever writes that record fills the operator in from the look that is running — a control turning exposure alone does not have to know one.

panel transport key - = ` MIDI cc → exposure MCP — CLI --exposure

Inside a Set

Everything about what a deck is. Almost none of it is reachable while running.

Write a parameter

launch

The sharpest gap here: a model can rewrite a whole procedure and cannot turn one knob. Moving a value today means editing the source and letting a hot swap rebuild it, which is a cold start rather than a uniform write. A bare name is one control per key and writes every node that declares it, so it is refused where those nodes are not under one authority, naming each of them and what it is under — one control spanning a node you kept and a node an agent acts on would hand over the first through the second. An address is never refused: it says which node it means. Nothing grants an authority yet, so nothing can meet this today.

panel inspector key — MIDI learned control MCP — CLI --param

launch

launch

panel inspector key — MIDI — MCP — CLI --capacity

Set a node's authority

immediate

Manual, suggesting or automatic, on one node of one deck's Set. It is a permission granted forward — what an agent may move from here on — and never a record of who moved something last, which is the source a driven parameter already shows beside its take back. Per node, never a global mode, because the useful arrangement is almost always partial. Every node a Set can address takes one, a kind Field node included: it draws nothing and its parameters are still an operator's to ride. The merge that folds a deck's renderers is the one node with no address, so it takes none. Nothing writes one yet, and what that means has changed: a deck carries authorities across a rebuild now, so the one thing missing is somebody to set one. Until then every node of every Set is manual, which is what a node nobody has spoken for is.

Procedures

Reading, writing and swapping the material itself.

Read one node's source

immediate

Addressed by deck, layer and index. Read before writing: the edit is usually small, and what is there is the best guide to the language.

panel inspector key — MIDI — MCP read_procedure

Check and write one node's source

on a worker

Checked as you write it; built on a worker and swapped at a frame boundary. If it does not compile, what comes back is the checker's diagnostics against the source.

on a worker

The same swap, reached from any editor. Polled, debounced, and compared by content rather than by timestamp.

panel — key — MIDI — MCP — CLI --watch

Find out what a write did

after the fact

Landed, rolled back for costing too much, or failed to build. A write returning cleanly means it compiled, not that it is on screen.

panel health readout key — MIDI — MCP swap_outcome

Keep a candidate

immediate

The operator's verdict on a version, and it is not the watchdog's. A version is on screen because it compiled and then held the frame budget over thirty measured frames — that is a judgement about cost, and whether it is the one to keep is a judgement about taste that nothing in this instrument can take. Keeping it settles the node and clears its row from the staging lane; nothing about the picture changes, because a write does not wait to land and the candidate is already what the deck is playing. It writes no record — the procedure change was recorded where the swap landed — which is why the words here are not the engine's accepted, rejected and rolled back: those name a build's cost verdict, and the lane is the one place both verdicts are read at once.

panel staging key — MIDI — MCP —

Put a node's previous version back

on a worker

What a rejected candidate costs nothing is made of. Every version that compiled is kept under the store's edit history — gated on compiling rather than on landing, so a real attempt that was rolled back for cost is exactly the one still there — and this puts the one before the current version back through the same check, build and frame-boundary swap any other write takes. One step, never a cursor: choosing among older versions is walk the edit history, which has no address anybody has settled. It names a node and not a source, because a lane can say not this one and cannot say four kilobytes of IR — the surface says the part it can say and whoever performs it reads the file. It does write a record, at the swap, like every other procedure change.

Arranging the console

The panel's own shape, which is the operator's and not the layout's.

Move a boundary

immediate

Every divider drags, and stops where the regions either side say they will go no further. A window dragged too small to hold everything gives everything less and forgets nothing: widen it again and the arrangement comes back exactly.

panel drag key — MIDI — MCP —

Fold a bay away

immediate

A folded bay takes no space at all and no divider is drawn beside it; what it had goes to the bay that takes height back in that pane. Its size is remembered, so bringing it back puts it where it was.

panel bay head key f g MIDI — MCP —

Fold a pane away

immediate

The whole left or right pane, with everything in it, and the centre takes the width. The centre is not a third pane and does not fold — what you want there is solo.

panel pane edge key f g MIDI — MCP —

Bring back what is folded

immediate

A folded region has no rectangle, so a pointer cannot reach it. That makes this the one operation here that a mouse cannot be the only way into — folding is one-way for a pointer, and something else has to undo it. z is that something else, and it brings back everything folded rather than one region, because a region a pointer cannot reach is a region a key has no way to name either.

panel — key z MIDI — MCP —

Solo a region

immediate

Everything that is not this region, on the way to it, or inside it folds away, and it holds the window. On the program that is the panel folding away and only the picture left, which is also how you capture this window. Undoing it restores what was folded before, including whatever was already folded.

panel solo key s u MIDI — MCP —

Reset the arrangement

immediate

The default arrangement back, in the window you already have. It is the one operation here that forgets, and what it forgets is what the rest of this section promises to keep: every fold, every boundary you have dragged, the solo, and the remembered sizes a folded bay and a window dragged too small are both holding for you. This is the special case of putting a saved arrangement back, and the two rows under it are the rest of that family: the default is one arrangement among the ones you could name, and it is the one that came with the program. It reaches code rather than a file, so there is no name it answers to and nothing you save can shadow it. A pad could name it: it addresses nothing, where every other row here needs a region a map line has no way to spell. None does yet.

panel transport key r MIDI — MCP —

Save the arrangement

immediate

The console as it stands — every fold, every boundary you have dragged, the solo and both sets of remembered sizes — filed under a name you pick, and saving over that name again is what you mean by saving it again. It goes beside your Sets rather than beside the program: arrangements/ under the store, so it travels with the library it was arranged around and nothing you save can reach what ships. The name is the whole of the handle, which is why you type one rather than being given a number: a slot moves when you delete the slot above it, and a name does not. The window it was saved at is not part of it.

panel transport key — MIDI — MCP —

Put a saved arrangement back

immediate

The arrangement you kept under that name, in the window you already have — the same sentence as the reset with a name in it, which is what makes the reset the special case rather than a convenience. The window is not restored. An arrangement carries the viewport it was saved at and comes back at the one you are looking at now, so a console arranged on a laptop opens on a projector without a margin round it. Two things are refused rather than guessed: a name nothing is filed under is said back to you and your console does not move, and an arrangement that disagrees with itself is refused whole rather than repaired into something you did not save.

What the gaps say

MIDI is the narrowest by a wide margin. It reaches eight of these fifty-five operations, and it cannot express a node address, a parameter name or an id — nor a bare number, which is why it reaches one half of the mask and not the other. A map line carries a slot number, a word out of a value list, or a range, and an angle is none of the three; a pad naming a shape alone would have to invent the angle beside it, and the map reads nothing back to invent it from. So the front has a fader and Set a deck's mask shape stays empty here rather than being given a route that guesses. That is settled and not outstanding: the two ways to fill the badge in are a number the format cannot check and an angle somebody defaults, and the thing that would decide between them is a control that shows an angle, which does not exist yet. It no longer has a vocabulary of its own, though: a map line names one of the operations on this page, and it names it outright — which state, which mode — rather than saying step it. It also has no idea of a selected deck — it names the deck in the message — where the command line's keys have nothing but the selected deck. The same operation is addressed two different ways on two surfaces.

The keyboard's twenty designed rows are one program's keys waiting for another's. This column is the instrument's keyboard, and twenty rows on it — across the transport, the decks, the mixer, the library and the window — are reached by pressing a key today, in karakuri-cli, which is not the program the panel is in. That is a gap of a kind none of the others here are: nothing is undecided, nothing is unspellable, and no control is unbuilt. The keys exist, they are specified on this page, and the window a player opens does not read them yet. What it waits on is the work of putting those operations behind the panel's own keyboard, and one decision beside it: which of the two keyboards keeps the seven letters they both want.

A model can rewrite a whole procedure and cannot turn one knob. MCP edits material, reports swaps and reads the library, and touches nothing in the mix, the clock or what is on air. It can make a deck unrecognisable and cannot put it on air.

Authority is named here and reachable from nothing, and it is short of something none of the other empty rows are. It is not waiting on a decision: rule 06 settled the address, and it is per node. It is not waiting on a control either — the node head it belongs on is specified on the console page, like every other panel route on this page. What it waited on was the deck, and the deck arrived. A node's authority has to survive every rebuild, the way that node's parameters and bindings already do, and a rebuild that let it be worked out afresh would hand a node back to an agent an operator had taken it from, saying nothing. A rebuild restates them now. What is missing is a writer — nothing sets one, so nothing has to survive yet, and the row is a word the instrument can keep and has never been told. That is a shorter list than the one this paragraph used to name, and naming the old blocker after it closed is how a row stays unbuilt for a reason nobody rechecks.

Arranging the console is reached from the keyboard, and until the instrument existed it was reachable from a pointer and nothing else — which is what this paragraph said, and it called it the first rule broken by the surface the first rule is about. Five of its eight rows are built in the key column and four in the panel column: f and g fold whatever the pointer is over, z brings everything back, s and u solo and unsolo, r resets, and the pointer has the drag and the arrangement pill's three. How a region is unfolded without a mouse is decided, and z is the answer: a folded region still has no rectangle, so a pointer still cannot reach it to undo itself, and it no longer has to. What is still short is the boundary. A divider is dragged and nothing else, because Layout::set_divider takes a viewport pixel and a key press cannot mean one — the vocabulary carries Move a boundary as undecided for exactly that reason. It is the one row here with no route but the pointer's, and it is what is left of the first rule being broken by the surface the first rule is about. Reset the arrangement is no longer waiting on the family it is the default case of in order to be reached at all — r performs it — but MIDI is still empty: it names no region, so a pad could reach it the way a pad reaches tap, and none does.

The two rows that carry a name were empty in every column, and a name is why. Keeping an arrangement and putting one back each carry a name the operator picked, and for as long as no surface could say one, no surface could reach them. The panel can say one now — it is the only one of the four that can — and the other three columns are still empty for the reasons below rather than for want of a control. A bare key press cannot type a name and there is nowhere on this console to show the operator a name it picked for them, so a keyboard route would file arrangements under stamps nobody could ask for again — and putting one back could not be bound at all, because nothing at a key press says which. A map line carries a slot number, a word from a closed list or a range, and a name is none of the three, which is the same refusal Load material into a deck meets over a Set id. MCP is the one surface whose grammar has no objection: it already spells a Set id, an arrangement name is the same shape, and the tools are simply not published. What these two waited on was one control, and it is built. The panel badges said where it went — the transport row, beside the map pill, which is already a named file with save, load and start a new one on it — the console page drew it, and the panel reaches all three rows now. It typed the name, which is what the other three surfaces still cannot do, so those columns are unchanged and empty for the reason above rather than for want of a control.

The command line is the only way into most of what a Set is — parameters, bindings, edges, the published interface, capacity — and it is only open before the run starts. Reachable from nothing at all while running: parameter writes, binding changes, edge rewiring, the camera, seeds, capacity, canvas size, un-compositing a deck, folding every renderer back in, a gain fade, and starting or stopping a recording.

Counted from the source, not from this manual. Where a row here and the program disagree, the program is right and this page is a bug — the seven rules are what both are meant to obey.
