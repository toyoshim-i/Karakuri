Karakuri · the manual

An instrument that writes its own material

Karakuri is a visual instrument. You keep Sets in a library, load one into each deck, and mix them live — and the material inside a Set is procedures that run on the GPU every frame, which you or a model can rewrite while it is on screen. This page is the seven rules the whole surface obeys. Everything else follows from them.

Seven rules, and they do not grow

01

One vocabulary, four ways in

Every operation that changes something — a write — is reachable from the panel, from the keyboard alone, from a mapped MIDI control, and from a model over MCP. There is no such operation only the mouse can reach, and none the map cannot address. An operation that only asks — a reading, a listing — is offered where a way in's own design wants it, and nothing compels it. What you learn on one surface you already know on the others, because they are the same named operations underneath.

02

You can always see who is holding a control, and always take it back

A parameter driven by something else shows its source instead of a number — a signal, a MIDI knob, a sequencer lane, an agent — and take back sits next to it. A control you cannot see being moved is one you cannot take, so nothing moves invisibly.

03

Density is bought with hover

The panel is dense because a performance is dense. Anything compact enough to be a symbol says three things when you point at it: what it is, what state it is in, and what a click will do. The third is what makes a symbol learnable rather than decorative.

04

Nothing is hidden quietly

A list that showed you part of itself says so and says how much. A control you cannot use says why it cannot be used rather than going grey without a reason. A procedure dropped for costing too much says that it was dropped. Silence is never the answer to something having gone differently than you asked.

05

Mixing is between decks; shaping is inside one

The mixer holds only what decides how much of each deck reaches the screen, and every channel stays visible so nothing scrolls out of reach mid transition. Everything about what a deck is lives in the inspector, where you can open more than one at a time and work on the deck that is not on air.

06

Authority is per node, never a global mode

Each node of a Set is manual, suggesting, or automatic, and you set that node by node. There is no switch that hands the whole instrument to an agent, because the useful arrangement is almost always partial: this geometry is yours and that renderer is not.

07

Sizes are the machine's answer, and the room is yours

Every divider drags, the program view can take the whole panel, and how many deck previews run is a control rather than a constant — because what a machine can afford is not something a layout should decide for it. Day and night are a choice you make, not one your operating system makes for you.

Why there are seven and not seventy

These are what you have to hold in your head before the panel makes sense, and a set of rules that keeps growing is a set nobody holds. So the list is capped: adding one means removing or merging one. That is a rule about this page rather than about the software, and it is the reason the page can be read once and trusted afterwards.

It is deliberately not the same kind of document as the principles the code is written to. Those accumulate, because a codebase learns. This one must not, because a mental model that grows is a mental model that breaks.
