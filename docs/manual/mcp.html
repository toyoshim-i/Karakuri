Karakuri · the manual

A partner that shares the console

Karakuri treats AI pair-programmers as live co-performers. Over the Model Context Protocol (MCP), an assistant can inspect active deck procedures, wire modulation graphs, author procedural shaders on the fly, and trigger musical operations — all subject to an explicit, bay-aligned permission model and live mixer tracking controlled directly from the performance console.

Connection & Protocol Architecture

Karakuri exposes an MCP server over HTTP JSON-RPC on the loopback interface when launched with the --mcp PORT flag: 

karakuri --mcp 8080

Standard MCP clients (such as Claude Desktop, Cursor, Gemini, or custom scripts) connect to the endpoint http://127.0.0.1:8080/. Every interaction obeys Karakuri's core architectural invariant: a surface offers, it never decides (Principle 0090). An assistant dispatches operations through the identical permission gates that govern keyboard and MIDI controls.

The Unified Gate Architecture & Protection Model

Live visual performance cannot tolerate broken shaders, frame stalls, or accidental mutations on material currently projected to an audience (Principle 0094). Rather than imposing a blanket restriction on the protocol, Karakuri maps each functional console bay 1:1 to an explicit protection gate:

Inspector Slot Pill (mcp · auto/on/off) Per-Slot (Deck A–D) Auto All shader code, parameters, bindings, and configurations in that specific slot
Mixer Bay Head Capsule (mcp · on/off) Global Bay Closed Channel faders, trims, mutes, solos, crossfader, wipes, and masks

Outputs Row Capsule (mcp · on/off) Global Row Closed External video sinks (Syphon/Spout/NDI), window routing, and session recording

1. Inspector Bay: Per-Slot Protection (Deck A–D)

The Inspector bay inspects and edits a slot's procedural tree (Layers L1–L5 and Field). Because co-performance relies on the operator driving the live picture while an agent prepares visual material in an off-air slot, Inspector protection is per-slot rather than an all-or-nothing bay lock:

  • Auto (Default): Automatically write-protects the slot while contributing to the main projection (tally == Live && opacity > 0.0). The moment the human operator pulls the fader down to 0.0 or mutes the channel, the slot leaves the mix and becomes immediately writable by the agent. Pushing the fader back up re-arms protection instantly.
  • On: The operator explicitly authorizes the agent to live-code this slot directly on air, with hot-reloading reflected live in the projection.
  • Off: The slot is strictly locked against all agent mutations, regardless of fader position.

2. Bay Class Gates: Coarse Safety Openings

The remaining console bays control shared stage surfaces. Their bay heads carry an interactive capsule (e.g. mcp · on / mcp · off). By default, all mutating operations targeting these bays are refused by the audit gate with a clear, actionable explanation until the operator intentionally clicks the bay header to grant permission.

3. Permanently Locked (Unclassed) Controls

Certain controls — specifically live musical tempo tapping (TapBeat), clock phase nudging (ScaleGrid), step sequence triggers, and application termination (Quit) — are unclassed and permanently barred from MCP control. These operations belong exclusively to the human performer on stage.

The M7 Co-Performance Tool Suite

Collaborative live coding requires rapid discovery and atomic staging. Three specialized workflow tools form the primary operational loop for autonomous agents:

01

get_permissions — Discover constraints before acting

Queries the live state of all console bays, per-slot MCP policies, whether each slot is currently contributing to the audience mix (in_mix), and whether it is writable. Agents call this at the start of a session to plan mutations only in authorized slots.

02

read_slot — Complete procedural inspection

Fetches the source code and configuration for all active procedural layers (L1 material, L2 deformation, L3 camera, L4 renderers, and Field distance functions) in a single roundtrip, eliminating multi-call assembly latency.

03

copy_slot — Safe rehearsal & duplication

Duplicates a complete visual setup from a source slot to a destination slot with atomic staging. A canonical live workflow is copying on-air Deck A to off-air Deck B, generating thematic variations with the agent, previewing them in Deck B's monitor, and transitioning them live with the mixer faders.

Machine-Readable Refusals & Autonomous Recovery

When an operation or tool call is refused by a gate, it is returned as an application-level tool error (isError: true) carrying a structured, machine-readable refusal object (Principle 0083): 

{
  "jsonrpc": "2.0",
  "id": 42,
  "result": {
    "isError": true,
    "content": [
      {
        "type": "text",
        "text": "deck 1 is protected by mcp policy: auto (currently in live mix)"
      }
    ],
    "refusal": {
      "code": "SLOT_IN_MIX",
      "slot": 0,
      "policy": "auto",
      "in_mix": true,
      "message": "deck 1 is protected by mcp policy: auto (currently in live mix)"
    }
  }
}

Standard Refusal Codes & Recommended Recovery

  • SLOT_IN_MIX: The target slot is active in the live projection under policy Auto.
    Agent strategy: Switch to an off-air slot (e.g. Deck B or C), or notify the operator that changes are staged and waiting for a transition.
    Operator action: Lower the slot's mixer fader to 0.0, or cycle its policy pill to mcp · on if live modification is desired.
  • SLOT_POLICY_OFF: The target slot is explicitly locked by the operator.
    Agent strategy: Do not retry mutations on this slot; query get_permissions to locate an unlocked slot.
    Operator action: Click the Inspector header pill to set the policy to Auto or On.
  • BAY_CLOSED: A functional bay required by an operate call is closed.
    Agent strategy: Inform the operator exactly which bay capsule needs to be opened (e.g. "Please open MixFaders in the Mixer bay").
    Operator action: Click the corresponding bay header capsule to toggle it to mcp · on.
  • SLOT_UNALLOCATED: The requested slot number does not exist in the active session.
    Agent strategy: Query get_permissions to discover valid slot numbers (typically 0 to 3).

Atomic Staging & Scratch Directory Safety

When an agent modifies or copies procedures, files are written first to adjacent temporary files (.kir.tmp) and replaced via atomic filesystem renames (scratch::write_atomic; ADR-0363). This guarantees that background compiler workers and filesystem watchers never observe partial AST writes or mismatched multi-layer interface changes mid-frame.
